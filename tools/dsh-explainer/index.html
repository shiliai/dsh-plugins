01

VERDICT

它不是一个 Agent 应用，而是一套 Agent 运行时

DSH 好玩的根本原因，是把完整 Agent 产品拆成了可组合内核、注册表、事件日志和作用域插件。插件作者只实现领域能力，模型循环、会话、权限、持久化和 UI 基础设施由底座承担。

适合

可信的本地插件、团队内部插件、垂直 Agent 产品和实验性多 Agent 工作流。

暂不适合

无审核公共插件市场，以及直接暴露公网的多租户 Agent 服务。

03

DESIGN PAYOFF

为什么开发插件会产生“随便怎么玩都行”的感觉

1

组合优先于继承

能力是可覆盖的 YAML 插件行。新增、替换、禁用通常不需要 fork 主程序，激活由服务可用性驱动。

2

循环故意保持很薄

AgentLoop 只负责“模型 → 工具 → 再请求”。压缩、重试、权限、计划模式和子 Agent 都挂在扩展点上。

3

ToolDefinition 贯穿全栈

一份定义同时驱动模型 Schema、参数校验、并发分类、执行流水线、Code Mode SDK 和 UI 展示。

4

Session 是事件源

聊天历史只是 append-only 日志上的投影，因此持久化、回放、压缩、分叉、统计都能独立演进。

5

每个 Agent 有独立能力视图

解析顺序是 agent → preset → global；同一进程可并行运行极简、代码和领域 Agent。

6

前端也有插件协议

浏览器 Bundle 通过 Slots 贡献侧栏、会话节点、详情面板和设置项，无需修改 Web Shell。

04

REQUEST FLOW

一次请求如何穿过系统

  1. 01
    Client

    提交消息，通过 RPC 进入 Host。

  2. 02
    Agent Inbox

    写入 durable splice，开启 Turn。

  3. 03
    Prompt Assembly

    按 Agent scope 汇总 Persona、上下文和可见工具。

  4. 04
    LLM Adapter

    流式返回 reasoning、文本和 tool-call chunks。

  5. 05
    Tool Pipeline

    pre-execute → guards → approval → execute → post-execute → result。

  6. 06
    Session Log

    记录 assistant/message、tool/call、tool/result 和边界事件。

  7. 07
    Next Step

    有工具结果则再次请求模型；没有工具调用则关闭 Turn。

  8. 08
    Browser Projection

    WebSocket 事件更新会话节点、工具卡片和详情视图。

工具调用存在时05 → 06 → 03形成可观察、可持久化的 Agent 循环

BOUNDARIES

真正需要提高警惕的地方

TRUST

插件不是安全沙箱

插件与 Preset 是可信同进程代码；用户 Preset 的实际权限可以等同 Shell。

ABI

当前仍是 RC 契约

Session 格式仍为 0，Client unload 尚有未完成部分。插件应锁定精确版本并跑真实 Profile E2E。

CONFIG

Patch 替换整段 config

它不是深合并；上游新增字段时，旧覆盖可能静默丢失默认值。

NETWORK

Web trust fence 不是认证

它解决浏览器可达性与 DNS rebinding，不构成公网多用户身份和授权层。

SCALE

默认架构偏本地单进程

分布式、多租户部署仍需补充远程执行、队列、租约、审计和一致性机制。

推荐定位

把 DSH 视为“可信、可组合、Local-first 的 Agent Runtime”。保留 AgentLoop，通过服务注册表、事件、Tools、Preset 和 UI Slots 扩展领域行为。
