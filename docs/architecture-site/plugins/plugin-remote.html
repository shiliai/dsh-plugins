dsh-remote：私有链接远程接入

把只绑在 127.0.0.1 的 dsh Web，经 SSH Unix-socket 反向隧道 + VPS 上的 Nginx 边缘，以「URL fragment 内 256-bit bearer」的私链形式安全暴露给远程浏览器。它是纯传输/信任层插件 —— 不注册工具、不碰 agent。

v0.3.3 · inject: [webServer] · 配套：dsh-remote-edge（VPS 布线器 bin）、install-dsh-remote-instance.sh（节点安装器）

apply 的三件事

// plugins/dsh-remote/src/index.ts:11-26
export const inject = ['webServer']
export function apply(ctx: Context, config: RemoteConfig) {
  installWebServerSocketCompatibility(ctx.webServer)  // ① 宿主 socket 兼容层
  remoteService.start(ctx.webServer, config)          // ② 网关 + 隧道 + 状态
  registerRemoteApi(ctx.webServer, service, …)        // ③ 管理 API
  return () => { … }                                   // ctx.effect 统一释放
}

① 是全插件唯一的「摸宿主内部」时刻：给 webServer 的 http.Server 每个连接挂空错误吸收器 —— DSH 在 close 时先移除了 upgrade 错误处理器，浏览器 reload 的迟到 transport error 会击穿进程。AGENTS.md 把「保留 commit d9022d1 的迟到 socket 保护」列为每个 release 的铁律，并有 dsh-compat 的自动化回归（建 upgrade 后 resetAndDestroy，确认进程仍存活）。

边缘网关的信任模型

面行为鉴权
POST /__dsh_remote/session票据换 cookie：私链 token → __Host-dsh_remote 会话 cookie（version.HMAC）；launchTicket → 经 Unix socket 找宿主侧 Go 程序赎回 → owner grant cookie（8h TTL、≤16 个、只存 SHA-256 digest）Origin 必须严格等于 remoteOrigin；body ≤1KB 精确两键
GET /（未认证）自举页：内联脚本从 URL fragment 取 token POST 换 cookie 后 history.replaceState 抹除 —— token 只出现在 fragment，永不进服务器日志/Referer/历史记录CSP default-src 'none'; script-src 'nonce-…'
其余 HTTP反代到 127.0.0.1:webServer.portcookie 会话 + Origin 检查；无 Origin 仅放行 GET/HEAD/OPTIONS
WebSocket仅 /api/events.mux、/api/events.hostcookie + Origin 双验；rotate 时踢掉旧会话 WS

远程降权：白名单反转

网关在 RPC 层区分「本机回环」与「远程」两种消费者：

  • 远程允许（以 loopback 权威代理）：MODEL_CONFIGURATION_METHODS —— settings.*、credentials.*、llm.discoverModels；
  • 远程一律 403：LOOPBACK_ONLY_METHODS —— agentPreset.*、host.pickDirectory、host.openPath 等文件系统/预设操作；
  • 调用者自标头 x-dsh-remote-* 进入即剥除、转发前再剥鉴权 cookie —— 防伪造与夹带。

这与宿主 packages/api 的 remotes 机制互补：api-remotes 用事件/方法白名单决定「什么能被远端消费」，dsh-remote 在其下一层决定「远端能不能到、以什么身份到」。客户端把 Settings 镜像切到 host 持久化也明确标注为「仅呈现态，网关从不以此作为授权事实」。

运维面与安装器

  • 管理 API（宿主 webServer 上，Origin 白名单）：GET status / POST rotate（轮换 token + sessionVersion 并踢旧 WS）/ POST reconnect。rotate 的落盘以原子 rename 为提交点：rename 前失败保旧链接，rename 后失败也报告已提交的新链接；所有比较 timingSafeEqual。
  • 配置即环境变量：mode/instanceId/baseDomain/sshTarget/socket/state/gatewayPort 全部 DSH_REMOTE_*，patch 文件是注入点；多实例模式下 origin/socket/state 都从 instanceId 派生。webServer 与网关必须绑 127.0.0.1，否则启动即抛。
  • dsh-remote-edge（bin）：把 Python 编排器 + 模板 scp 到 VPS 的 mode-700 临时目录 sudo 执行后清理；Hub 模式管多实例注册表，instance add/remove 先 nginx -t 再原子 reload、失败自动还原。
  • install-dsh-remote-instance.sh：备份回滚目录 → 按 SHA-256 留存 tarball → trap 式两阶段提交 → dsh plugin add → 写 systemd user unit → 轮询健康到 200 才提交；linger 需显式授权。

值得带走的设计点

  • 私链安全栈：fragment → HttpOnly __Host- cookie → history 抹除；cookie = version.HMAC(token)，轮换即全量失效；grant 明文永不落盘。
  • 对宿主韧性的责任：插件可以（也应当）为宿主的已知脆弱点提供防护层，但要把这类行为写进仓库纪律（AGENTS.md）并配自动化回归 —— 防护本身成为发布契约。
  • patch 的能力替换用法：remote 的 cordis.patch.yml 不只 insert 自己，还把宿主的自动目录选择器 disabled: true 换成显式 browse 实现 —— 补丁层可以换掉产品的某块行为而不改宿主。
