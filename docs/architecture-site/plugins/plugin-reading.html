dsh-reading：沉浸式阅读工作台

EPUB/PDF（AZW3/MOBI 经 Calibre 转换）阅读 + Wallabag 稍后读 + NAS Calibre-Web OPDS 书库 + MathJax 公式渲染的三栏工作台。它是「纯旁路」集成的代表：服务端只消费 webServer，内容进对话全靠客户端的草稿文本块。

v0.7.0 · inject: [webServer] · 零 agent 工具（刻意）

核心设计：四层缓存/状态

#层位置策略
1适配器内存缓存进程内Wallabag 60s / OPDS 5min TTL
2磁盘缓存（remote-cache）$DSH_HOME/cache/dsh-reading/<ns>/<sha1(key)>.jsonstale-while-revalidate：成功异步回写；远端失败回读旧值兜底。策略经 /settings API 向前端自描述
3项目目录缓存（project-cache）<dataDir>/workspaces/<sha1前12>-<slug>/每本书/文章一个项目目录：原文件 + article.md + 原子写入的 metadata.json（含 AZW3→EPUB 转换结果复用）
4状态库（state-store）state.json进度 + 批注；promise 链串行写、temp+rename 原子替换、快照 structuredClone 防泄漏；注释明确「留出换 SQLite 的余地」

HTTP API 要点

前缀 /dsh-reading/api（kind: prefix）。约 15 个端点：library / settings / project（书与文章的项目化，AZW3/MOBI 调 ebook-convert 120s 超时）/ opds（书目 + import）/ progress / wallabag（列表 + 按 URL 收藏）/ annotations / /book/:id/file（Range/206 流式，PDF.js 必需）/ import（上传 ≤512MB）。

服务端路径保密所有书以 PublicBook = Omit<Book, 'filePath'> 返回 —— 文件系统路径永不出 API，文件只经 /book/:id/file 按 id 流出。书架 API 的泄露面为零。写操作同源策略：带 Origin 必须同源，无 Origin 放行（兼容非浏览器客户端）—— 与 obsidian 的「严格 mutationOrigin」形成对照，三种松紧对应三种威胁模型。

内容如何进入对话上下文

服务端与 session/agent 零耦合，三条路径全在 client：

  1. 元数据块注入草稿：articleContext()/bookContext() 生成 [Reading item] 文本块（含 projectPath，并提示 cached at projectPath/article.md; use that file for the full reading text），经 ctx.conversation.input.for(actx).setDraft() 追加进当前会话输入 —— agent 随后用宿主自己的文件工具读全文。这就是「进上下文」的全部机制：插件不做 RAG、不改消息协议。
  2. 跨插件上下文：fetch /dsh-obsidian/api/context?kind=directory&value=reading，把 vault 的 reading 目录文件清单也追加进草稿 —— 插件间协作走各自公开的 HTTP API。
  3. 打开即建会话（createSessionOnOpen）：ctx.workspaces.create({path}) → connect → ctx.sessions.open(sessionId) —— 每本书/文章一个专属 workspace + 会话。

Web 客户端

  • 三个注册面：settings.plugins.tab（id dsh-reading、order 50，面板标题带 v{pluginVersion} —— 版本经 import pkg from '../../package.json' with {type:'json'} 构建期烘焙）；sidebar.footer.action 的书本按钮；shell.overlay 里 portal 挂载的三栏工作台。
  • 双阅读引擎：foliate-js（EPUB，进度 locator 是 cfi+chapterHref）与 PDF.js（worker 以 ?dsh-raw 内联成 blob URL，locator 是 page+scrollRatio）；文章 locator 是 scrollRatio —— 三态 Locator 是进度系统的心脏。
  • MathJax 懒加载：检测到 \(...\)/\[...\] 定界符才加载 mathjax-full（TeX 输入 + SVG 输出、无网络字体），TreeWalker 原地替换文本节点，编译失败回退字面量。
  • Contextmenu：「发送元数据到当前对话 / 打开本篇新对话」—— 把工作台与对话流缝合的两个动作。

值得带走的设计点

  • contracts.ts 是插件的类型级 API：同一份契约文件被 server 与 client 两侧 import —— 这是 dsh 宿主「宿主包发 .d.ts、消费方声明合并」模式在插件内部的缩小版。
  • 外部服务凭据分两路：环境变量或 $DSH_HOME/.credentials.yaml flat mapping；OAuth2 token 内存缓存提前 30s 过期；文章 HTML 过 sanitize（剥 script/iframe/on* 属性）。
  • 每层缓存的失效策略都自描述：/settings 把数据源与缓存策略摘要返回给前端 —— 调试「为什么没刷新」不用翻代码。
