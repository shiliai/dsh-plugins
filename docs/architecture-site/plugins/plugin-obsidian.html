dsh-obsidian：笔记库工作台 + vault 级技能

直接操作本地 vault 目录（不要求 Obsidian 运行、无 URI、无 REST）：浏览器工作台浏览/编辑/预览、thoughts 收集箱、8 个 vault 限定的 agent 工具、以及跟随当前 vault 的 agent 技能。集成模式上它同时用了「提供工具」与「注册 provider」。

v0.5.0 · inject: [webServer, tools, skills]

8 个 agent 工具

工具用途要点
obsidian_list_notes列 vault 内全部 .mdcursor/limit(1-500)/prefix 分页
obsidian_read_note读单篇返回 modifiedMs 供并发控制
obsidian_search_notes全文+路径搜索结果 path:line: excerpt
obsidian_list_tags / obsidian_search_by_tag标签索引与按标签查找frontmatter + 行内 #tag；嵌套标签祖先链；15s TTL 缓存 + 代数失效
obsidian_write_note创建/整篇替换替换必须带 expectedModifiedMs（mtime 乐观锁）；diff 卡片渲染
obsidian_move_note / obsidian_delete_note移动 / 物理删除不覆盖已有；删除描述强调「仅在用户明确要求时调用」

读类工具全部声明 isConcurrencySafe: () => true。

vault 安全监狱（把 LLM 当不可信调用方）

VaultService 是自研的「vault 限定 fs 层」，与宿主 fs/workspace 服务无关（inject 列表里没有它们）：

  • 路径安全：拒绝 \0/反斜杠/绝对路径/..；逐段 lstat 拒绝 symlink；解析后再次 realpath 确认没逃出 vault；跳过 .obsidian/.git/node_modules；只处理 .md 与白名单图片；
  • 并发写：文件已存在而无 expectedModifiedMs → 409 NOTE_EXISTS；mtime 不符 → 409 NOTE_CONFLICT；临时文件 wx 写 + rename 原子替换；move 用 link+unlink；所有变更经 promise 链串行；
  • HTTP 侧：一切变更操作要求 Origin 存在且严格等于配置的 mutationOrigin（normalizeOrigin 拒绝带 path/凭据的 Origin）。

vault 级技能：全局注册、闭包换库

技能存放在 <vault>/.agents/skills/<name>/SKILL.md，revision = 内容 sha256，create/update/delete 带碰撞检测与失败回滚。妙处在注册方式：

// plugins/dsh-obsidian/src/index.ts:52-57（精简）
// provider 注册在「全局层」—— 每个 agent 都能看到当前 vault 的技能；
// provider 实例不绑定具体 vault，切换 vault 时 setStore + 宿主 invalidate()
ctx.effect(() => ctx.skills.registerProvider((control) => provider), 'dsh-obsidian: skills')
…
onVaultChange: () => { rebuildStore(); provider.setStore(store); ctx.skills.invalidate?.() }

技能集合动态跟随工作区而不重复注册；宿主技能注册表通过 invalidate 通知重列（SkillCoordinator 在每次变更后广播）。这套结构使「换一个 vault = 换一套 agent 技能」成为纯数据操作。

Web 客户端：动态槽位选位

  • 四个注册面：settings.plugins.tab（Obsidian skills 面板 + slim 版本条）、sidebar.footer.action 两个按钮（工作台 / Thoughts）、sidebar.workspaces 的 VaultBrowser（目录树 + 搜索 + 标签 + 换 vault）、以及 NotePanel 的动态挂载目标 —— 按会话状态在 conversation / conversation.session / details 三个槽位间迁移，details 目标还会自动 ctx.layout.openDetails()。
  • 工作台与 reading 同构：portal 叠加 + [data-phase] 锚点 + 纯函数几何；MarkdownPreview 用 marked + DOMPurify，双链 [[...]] 可点击跳转。
  • 进上下文与 reading 同款：NotePanel「加入对话上下文」→ [Obsidian context] 文本块（type/vault/directory/absolutePath/recursive/文件清单）追加进草稿，agent 再用 obsidian_* 工具拉取真正内容。
  • thoughts 收集箱：GTD 式，存 vault 内隐藏目录的按日 md 文件，每条是 - [ ] 文本 <!-- dsh-thought id status created --> 标记行 —— 数据即 Markdown，用户在 Obsidian 里也能直接编辑。

值得带走的设计点

  • patch 默认值即用法：cordis.patch.yml 里 vaultRoot: !!js process.cwd() —— 支持 cd <vault> && dsh web 的直觉用法；正式部署在 profile 用户层用 - id: dsh-obsidian, config: {vaultRoot: …} 覆盖（记得整行复述）。
  • 乐观锁针对的是「模型并发」：expectedModifiedMs 不是给人用的 —— 是把 agent 的并发写变成结构化 409 的机制，与宿主工具管线的守卫语义互补。
  • provider 的 rank 语义：rank 300 排在本地 provider 之后 —— 插件技能与宿主技能的关系是「补充」，注册表负责排序与失效，插件不抢占。
