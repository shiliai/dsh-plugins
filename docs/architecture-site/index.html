dsh 是什么

DeepSeek Harness（dsh）是一个 agent 运行时：它管理会话、驱动模型循环、执行工具、对外提供 Web UI / SDK / ACP 等入口。它没有把任何一个这些能力写死在内核里 —— 官方 README 的第一句定位就是 an architecture where everything is a plugin，底层是 Cordis 插件容器（其设计论文题为《A Programming Paradigm for Spatiotemporal Composability》）。模型适配器、工具注册表、会话日志、甚至 agent 循环本身，都是挂在同一棵插件树上的普通插件 —— 所以每一个都可以被配置替换。

官方原文（docs/architecture.md:13）：There is no privileged core to patch: you extend dsh by mounting a plugin beside the others, and registrations are effects that unwind when their plugin unloads.
—— 没有「需要打补丁的特权内核」：扩展 dsh 的唯一方式就是把一个插件挂到其他插件旁边；一切注册都是可逆的副作用（effect），插件卸载时自动展开回收。

进程结构上，一条 dsh --profile web 命令启动的是：launcher（apps/cli，8KB）→ profile 组合器 → Cordis 容器 → 约 100 个插件组成的树。launcher 只负责「选哪棵树、叠哪些层」，其余一切（解析 --port、绑定 HTTP、跑 agent）都发生在树内的插件里。

设计思想（从源码与文档中提炼）

这十条是我们研究过程中反复被验证的「dsh 味道」，每一条都能在我们自己的插件里找到对应的实践：

思想含义我们插件的印证
1. 一切皆插件 模型适配器、工具注册表、会话存储、agent 循环、Web 服务器都是插件，没有特权内核。 dsh-wecom 与官方 web-startup 插件在 Cordis 眼里没有区别，都是一行 entry。
2. 组合即数据 产品 = 插件树，而树 = 补丁层的和。根 cordis.yml 恒为 []，一切行都由 patch 叠加而来。 实机 ~/.local/dsh_home/profiles/web/cordis.yml 就是 []；我们 5 个插件各自一个 cordis.patch.yml。
3. 服务即依赖（inject） 插件用 inject 声明消费哪些服务，框架等依赖就绪才挂载；顺序由数据表达，不写引导代码。 wecom 声明 inject: [tools, agents, agentPresets, sessions, webServer…]，reading 只需 [webServer]。
4. 注册即可逆副作用 一切经 ctx 的注册（工具/监听/路由/定时器）在卸载时自动回收，HMR 因此安全。 每个插件 apply() 末尾的 ctx.effect(…)；改 profile 的 patch 文件无需重启即可换行。
5. 事件即扩展点 拦截与观察走类型化事件（emit / waterfall / serial / parallel），不做侵入式钩子。 wecom 镜像 web 消息靠订阅全局 session/event；宿主 ask_user_question 的路由靠 agent/pre-step。
6. 日志即真相 Session log 是 append-only 事实流；凡模型可见必已落日志，UI/恢复/fork 全部从日志投影。 wecom 的回合摘要 summarizeTurn() 就是读会话事件后缀生成回复 —— 与浏览器看到的是同一份事实。
7. 能力缝（seam）三角色 可替换能力 = Service Definition（接口）+ Provider（实现）+ Consumer（常为模型工具），换 Provider 即换产品行为。 dsh-obsidian 的 skills provider（rank 300）只是往 ctx.skills 又挂了一个 Provider；sessionPersistence 可换 JSONL/SQLite。
8. 整行替换的补丁语义 patch 按 id 定位、整体替换 config、不深合并 —— 防止「幽灵默认值」，每行最终值只在唯一一层可见。 实机 profile 覆盖 dsh-wecom 白名单时必须复述 botId/botSecret，源码注释里就写着这条纪律。
9. launcher 不认识应用 launcher 只解析 --profile/--patch/--dump-*，其余参数原样下传；应用 flag 通过「命令行服务」压过配置。 port: !!js ctx.webStartup.port ?? 3080 —— 我们从未为支持任何 flag 改过宿主。
10. fail loud 与安全默认 配置坏在加载期、缺服务列名字、遥测默认可关、--host 0.0.0.0 直接拒绝；安全不在框架层假大空，而在每个插件各管各的路由信任。 wecom 空白名单=拒绝、remote 网关强制 127.0.0.1 + Origin 校验、obsidian 的 symlink 监狱。
